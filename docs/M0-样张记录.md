## 第二轮：把"绚丽"补上

第一轮出来的是干净的白纸 + 平涂，**不够绚丽**。回头对比参考书（`_analysis/pages_a/`），
它的能量来自三件事，都不是平涂：

1. **笔触本身**：大笔触、边缘毛躁、笔画里有飞白（干笔）。
2. **大色块**：斜向色带、放射线、漩涡、实心圆盘，铺满整页。
3. **大号手写字压在色块上**。

于是新增 `tools/gen-effects.py`：沿中心线生成"笔画"（带宽度变化、两端平切的闭合路径），
再在笔画里嵌几条细的纸白飞白。产物 `src/components/effects.svg`（约 130 KB，确定性可重跑）：

| 符号 | 用途 | 用在哪 |
|---|---|---|
| `prop-rays` | 11 条粗放射线 | p05 魔法时刻、p08 满版红 |
| `prop-rays-tight` | 13 条细放射线 | p06 凑近时的光晕 |
| `prop-swirl` | 一笔画的螺旋色带 | 备用（M1 用） |
| `prop-disc` | 实心圆盘 + 零散飞白 | p07 托着红苹果 |

同色系深浅交替（`--ray` / `--ray2`），纸白飞白用 `--ray-gap`——
红底页上飞白要跟底色一致，否则像划痕。

逐页配色（按语义）：p05 黄＝魔法/兴奋；p06 粉＝甜/友好；p07 蓝盘托红苹果（补色对比）；
p08 满版红 + 深红放射线。拟声词也改成参考书那种**横贯页顶的大字压在色块上**（p05 11u 一行）。

## 第三轮：效果要变，色块要长在页面上

反馈是"为什么一直都是射线"+"一些色块明显分离"。两件事都不是调参数能解决的，是缺一层系统：

### 1. 笔触词汇表（`tools/gen-effects.py` → `src/components/effects.svg`）

| 符号 | 形态 | 特点 |
|---|---|---|
| `fx-rays` | 放射线 | 角色身后的爆发；留给高潮页 |
| `fx-rays-tight` | 细放射线 | 贴着角色的一圈光 |
| `fx-rays-corner` | 角落爆闪 | 从页面一角冲进来，直接冲出画外 |
| `fx-bands` | 斜向色带 | 整页铺满，**不留白岛**（参考书 p11） |
| `fx-swirl` | 漩涡 | 一笔画的粗螺旋（参考书 p03） |
| `fx-disc` | 实心圆盘 | 放大放置即出血压边 |
| `fx-confetti` | 彩纸 96 片 | 位置固定（规格 §7.8），M1 的 S7 用 |

笔画统一由 `ribbon()` 生成：沿中心线、宽度有变化、两端平切；再叠一层**边缘抖动**（`rough`）
做出马克笔的毛边，笔画里嵌细的纸白**飞白**。同色系深浅交替（`--ray` / `--ray2`），
红底页的飞白跟底色一致（`--ray-gap`），否则像划痕。

### 2. 尺寸规则（重排）

- **色块必须出血，不能浮在纸上。** 圆盘放大到 1080 并下移 → 压住下边缘；漩涡出画外；
  色带整页铺满。画外被裁切才是"长在页面上"。
- **角色与色块要有关系**：放射线的圆心对齐角色肚子；漩涡起笔藏在角色身后（`start_deg`）；
  角色压在色块之上。
- **角色占比**：t-dialog 62%（p05）/ 72%（p06，凑近是例外）；t-food 食物 36%；t-color 76%。
- **字**：p05 拟声词 11u 横贯页顶压在色带上（参考书 p05 的做法），其余页拟声词 14–16u。

### 3. 四页各用一种（不重复）

## 第四轮：笔触被切出一条直边

截图上能看到：p06 的漩涡在左边被竖着切掉一块，p08 的放射线在上方被横着切掉一块，
切边是**笔直的**——这正是 bug 的样子（手绘笔触不可能有直边）。

**根因**：`<use>` 引用 `<symbol>` 时会建立一个视口（x / y / width / height），
symbol 里超出视口的内容**被裁掉**。我把效果正好摆在视口边界上：

- p08 `<use href="#fx-rays" x="0" y="180" width="1000" height="1000">` → 视口上沿在 y=180 → 上面的射线被裁 → 横切线；
- p06 `<use href="#fx-swirl" x="220" y="40" …>` → 视口左沿 x=220、上沿 y=40 → 竖切 + 横切；
- p07 的蓝色圆盘同理，只是它的切口被当成了"山丘的形状"，没被当成 bug 看出来。

**修法（根治）**：所有组件从 `<symbol>` 改成 `<g>`，摆放一律用 `transform`。
`<g>` 没有视口，`<use>` 只是克隆，不会裁剪；缩放/位移改用 `translate()` / `scale()`。
角色、道具、笔触三套组件一起改。

顺带修掉两个连带问题：

1. 漩涡内圈半径（120）小于笔宽（124），带状路径自交，甩出一片"叶片"状怪块 →
   内径提到 200、笔宽 52，2.4 圈；
2. `check-pages.mjs` 原来只认 `<symbol id>`，组件换成 `<g>` 后误报"符号不存在" → 改成两种都认。

> 往后放任何会出血的素材（笔触、背景、裁切到画外的图形），都用 `<g>` + `transform`；
> `<symbol>` 只留给"必须自带视口比例"的东西（本项目里已经没有这种用法了）。

## 第五轮：字体授权

要求是"必须用可商用授权的"。核验结果：**现在打进书里的两套字体本来就是可商用的**——
`@fontsource/zcool-kuaile` 与 `@fontsource/lxgw-wenkai` 的 `LICENSE` 原文都写着
"This Font Software is licensed under the SIL Open Font License, Version 1.1"，
且都**没有声明 Reserved Font Name**（OFL 文中出现的只是术语定义，不是保留名声明）。

之前那句"站酷商用授权未确认"来自设计规格里"站酷官网分发条款"的备注；
而本项目用的是 @fontsource（源自 googlefonts/zcool-kuaile）的 OFL 1.1 版本，两回事。

为了不让这条只停在口头，新加**授权闸门** `tools/check-licenses.mjs`（进 `npm run check`）：

- 逐个字体包读 LICENSE，白名单＝OFL 1.1 / OFL 1.0 / Apache-2.0 / MIT；
- 出现"仅供个人使用 / 非商用 / personal use only"等表述 → 失败；
- 声明了保留字体名 → 失败（子集必须改名才能出版）；
- 子集产物缺失 → 失败。

已做过反向验证：塞一个只有 "personal use only" 的假字体包进去，检查确实拦下并返回退出码 1，随后清理。

**一条纪律**：不要从站酷官网手动替换字体文件——官网版条款与 OFL 版不同。

## 相对设计规格的调整

1. **零件外观改为元素内联样式。**
   规格 §7.4 说"CSS 变量控制颜色"，但没说清实现约束：`<use>` 引用后内容落在影子树里，文档 CSS 选择器对影子树不生效。
   所以 `components/*.svg` 里每个零件写成内联 `style="fill:var(--body);stroke:var(--ink);stroke-width:var(--line)"`，
   颜色状态仍由 `.state-red` 等类的 CSS 变量控制（自定义属性能穿透影子树）。页面上的写法不变。

2. **螺旋从姿态里拆出来，单独一行 `<use>`。**
   否则文档 CSS 转不到影子树里的螺旋，"屏幕上慢转"做不了。
   `pose-*` 不含螺旋，页面额外引用 `<use href="#ch-spiral" class="spiral">`。

3. **满版色页：角色身体 = 页面色，靠粗黑线与白色细节撑形。**
   规格 §6.2 只说"正文放在白色手绘底块上"，没定角色怎么办。按参考书 p54 的做法（角色与底色同色、靠黑线定义形状）实现，
   眼白、瞳孔、舌头保持白色/深色对比。p08 实测成立。

4. **印刷版版式提到常规 CSS 层。**
   规格 §8.2 的打印规则原本都写在 `@media print` 里，导致 `print.html` 在屏幕上预览时整页隐藏（无法逐页出图）。
   现在 `body.print .page` 的尺寸规则在常规层，`@media print` 里只留 `@page` 与分页符。

5. **新增 `dist/proof.html`。**
   规格 §9.3 说用 `?static=1` 出图；实际出图走 `proof.html`（body 带 `static` 类），
   页面固定 720 × 720 CSS px，配合 `--dpr 2` 出 1440 × 1440。`?static=1` 仍然可用。

6. **颜色状态里的 `--spiral` 用墨色，不用规格 §7.4 建议的深红。**
   满版红页上深红螺旋会消失在同色身体里。墨色在所有颜色状态下都可读。

7. **新增 `tools/smoke.mjs`（交互冒烟）与 `tools/shots.mjs`（html-shot 封装）。**
   规格 §9.2 只列了"Playwright 冒烟"，本轮先落成可跑的脚本。

8. **新增笔触特效层与颜色令牌。**
   规格 §3.2 提到"黄放射线、红放射线、彩色烟花"是高潮元素，但 §6.6 的七套模板里没有对应位置。
   本轮补了七个笔触符号（见上表），并新增 `--yellow-deep`、`--pink-deep`、`--ray`、`--ray2`、
   `--ray-gap`、`--disc`、`--confetti-*` 共十个令牌。
   规格 §6.2 的"每页最多 3 个填充色"仍成立（p05 黄+深黄+白、黑；p08 红+深红+白、黑）。

## 待用户确认（画风确认点）

1. **角色线条的"手绘感"够不够。** 当前身体是抖动圆（确定性生成），线宽 26（角色占 60% 页高时约 3 mm），
   比参考书略细、略规整。参考书线条更粗更毛躁。要更接近参考书，可加大线宽与抖动。
2. **角色是否够"圆"。** 噜啵目前是一个团子 + 螺旋 + 圆点眼 + 腮红，很干净。
   参考书角色是单眼 + 王冠 + 豆形身体，形态更怪。本项目按规格 §4.3 走"圆身体 + 大嘴 + 螺旋"。
3. **满版色页的同色处理。** 角色与底色同色、只靠黑线分离，是本轮的取舍；另一种做法是角色保留纸白身体、只让页面变色。
4. **手写字体。** 拟声词用站酷快乐体（逐字 ±3° 抖动），旁白用霞鹜文楷。
   参考书全用手写体；当前是"拟声词手写 + 旁白楷体"的分工，旁白是给大人念的，字要清楚。
   （授权已核验：两套都是 SIL OFL 1.1，可商用、可嵌入出版物，见 `LICENSES.md`
   与 `tools/check-licenses.mjs` 闸门。）
5. **笔触层的强度。** 现在的笔画是平涂 + 飞白 + 毛边，接近参考书但更干净；
   若要更接近真实马克笔，可以给同色系再叠一层半透明笔触。
6. **p06 的留白。** 左栏只有两行字、右侧一个凑近的角色，留白约 55%。是否需要再加一点信息（例：一个小道具）？

## M1 之后的第三轮：页面框架 + 剧情加料

反馈有三条：每页要能自定义尺寸、背景要布满全局；不要每幅都手写 HTML；剧情比参考书无聊。

### 1. 页面框架（改版式只改框架）

每页从"一份手写 HTML"改成"一份数据"（`src/content/specs/*.js`），
由 `tools/render-page.mjs` 渲染成 HTML。带来的东西：

- **坐标统一成页宽千分比**（0–1000），和画布 viewBox 同一套；
- **背景自动布满全局**：放大倍数 = 焦点到页面最远角的距离 ÷ 特效半径，
  由框架算，页面只声明"焦点在哪、什么颜色"；`cover: 'x' | 'y' | 'all' | 'none'` 控制方向。
  以前每页手调 `translate/scale` 才能让笔触出血，现在声明即满版。
- **热点可以给一组**：p13 的三样、p27 的三个道具各是三个独立热点。
- **页面清单只有一份**：`load-specs.mjs` 读出来，构建、检查、字体子集、截图全部共用。
  `src/content/pages/*.html` 已删除。

### 2. 剧情加料

原来的四拍「喂→变色」太可预测。参考书的趣味来自**意外**（"我能看见你！"、
找眼睛、吹气飞行、烟花），所以：

| 页 | 改动 |
|---|---|
| p06 | 旁白改成「是我，噜啵。我看见你啦！」——**打破第四面墙**，全书第一个意外 |

| p20 | 原来的「谢谢你」换成**彩纸把噜啵卷起来，送到天上啦！**——飞走（参考书的飞行梗） |
| p27 | 「找一找」升级成**噜啵躲起来了**，找齐三样它才蹦出来 |

保留原有的核心：红蓝黄三色、彩虹、鼓成球、打嗝喷彩纸、褪色、晚安、第二天——这些是节奏骨架。

### 3. 管道换成成熟工具

反馈问"没有成熟框架和依赖可以直接用吗"——对，**管道这一层不该手写**。

- 换成 **Vite + vite-plugin-singlefile**：CSS/JS 打包压缩、字体 base64 内联、开发服务器都白拿，
  产物仍是三个单文件 HTML（`dist/index.html` 屏幕版 28 页、`dist/print.html` 印刷版 32 页、`dist/proof.html` 拼版）。
- 页面模板换成 **Handlebars**（`src/templates/page.hbs`）：模板里不写逻辑，
  数据 → 视图模型 → 模板，模板可读、可单独改版式。
- 手写的 `tools/build.mjs`（拼 CSS/JS + 手工 base64 字体）已删除。
- 自研只剩两件事，且都只是"算一下"：
  **背景放大倍数**（保证笔触布满全局）与**拟声词逐字微转**——
  这是本书特有的画法规则，没有现成实现，算完就交给模板。

### 5. 这轮踩到的坑

1. **拟声词条目漏了文案** → 整本书渲染出 32 个 "undefined"。
   检查器当时只查"键存在"，没查"值有内容" → 现在 `text.*` 没有文案就报错 ✓。
2. **只给一个颜色时 `--ray2` 回落成全局默认色** → 蓝页里混进黄色射线。
   现在只给一个颜色时第二色跟随第一色 ✓。
3. **模板变体漏写** → p10（该蓝底）渲染成红底，因为模板串写成了 `t-color` 而不是 `t-color t-blue`。
4. **PowerShell 字符串替换翻车**：嵌套数组被压平，`$e[0]/$e[1]` 变成字符串首两个字符，
   于是执行了 `Replace('t','r')`，把三个 spec 文件里每个 t 都改成了 r
   （`true`→`rrue`、`at:`→`ar:`、`export`→`exporr`）。
   **教训：改源码用编辑工具或写成文件的脚本，别用 PowerShell 的 `.Replace()` 做批量替换。**
5. **Vite 默认清空 dist/**，把刚出的截图与印刷 PDF 一起抹了 →
   改成 `emptyOutDir: false`，另给 `npm run clean`。
6. **`check-text.py` 断了却没人发现**：页面数据搬到 specs 后它还在读旧的 book.json，
   而我当时用 `Select-String "通过"` 过滤输出，把失败盖住了。
   **教训：别过滤检查的输出，失败要看得见。** 现在它直接读 `dump-text.mjs --json` ✓。

### 6. 版式检查（`tools/check-layout.mjs`）

用 Playwright 量每段文字的**墨迹范围**（Range.getClientRects，不是元素盒子——
居中排版的盒子比文字宽得多，量盒子会误判），查三类问题：

- 文字互相重叠（大字压小字）✓
- 文字越出安全边距（页面边的 6%）✓
- 文字被容器裁掉 ✓

第一次跑出 **54 处**问题（含 4 处大字压小字）。修完加了三条机制：

- **渲染器自动缩排**：文字太宽就自动缩字号（`fitSize`）——
  算宽度要按"最长的一行"算，多行文本按整段算会把版权页小字撑成 8u；
  还要注意 `size` 是 u、`at` 是千分比，1u = 10 千分比；
- **拟声词行高 0.95 → 1.1**：行高小于 1 时字形会溢出盒子，位置就不可控；
- 文字位置统一收进安全边距。

现在全书 0 处重叠、0 处越界、0 处裁切 ✓，并进 `npm run check` 盯着。

### 7. 小字改成"绘本字"

旁白原来用霞鹜文楷 **Light 300**——细、正、经，像课本不像绘本。
换成 **500 粗细**（毛笔楷的粗笔触），字距 0.06em；大人提示同样处理。
参考书里大小字都是手写毛笔字，这是"不像绘本"的主因。

> 字重档位说明（2026-10-30 核对 `@fontsource/lxgw-wenkai` 5.3.0）：
> 它给三档——`300` = **Light**、`500` = **Regular**、`700` = **Bold**。
> 所以 CSS 里的 `font-weight: 500` 取到的是 **Regular 那一刀**（确实比 Light 粗），
> 但 PDF 里嵌进去的字体名会显示 `LXGWWenKai-Regular`、`usWeightClass=400`——
> 那是字体自己的 name table，不是渲染没生效。
> 实拍确认旁白已是毛笔楷的手写感 ✓。

## 第二轮审查（交互状态机，2026-10-30 续）

第一轮只覆盖了"闸门与结构"，没深挖交互状态机。这轮实测出 **7 处真 bug**，
其中 4 处是同一个根因的不同表现。

### 根因 A：`page` 传成了 DOM 元素，`pageId` 当字符串用

`interactions.js` 里 10 处 `Book.after(750, fn, page)` 传的是**页面元素**，
`book.js` 的 `after(ms, fn, pageId)` 却把第三个参数当 **id 字符串**用。
于是所有页面的计时器键都退化成同一个 `"[object HTMLDivElement]"`：

- "这一页的效果"和"别页的效果"分不开 → 上一页的计时器会吃掉下一页的点击；
- 计时器到期时执行 `Book.next()`，翻的是**读者当前所在页**，不是这个效果该去的页 →
  p15 的残留计时器把读者从 p25 翻成了 p26；
- 修第一版时又踩了一次：加"到期时校验当前页"的守卫，因为键是脏的，**所有效果都被丢弃**，
  点肚子不翻页了。

**修法**：`book.js` 里加 `pageKey()` 统一归一化（元素或 id 都接受），
参数类型不认识时**直接抛错**，不再静默合并成一个键。

### 根因 B：换页不作废在飞效果

`show()` 只换页，不清上一页还在计时的效果。读者离开一页后，那个"翻页"还在跑；
等他回头再进那一页，计时器到期会把他莫名翻走。

**修法**：确立不变量——**任一时刻最多只有一个待定效果，且它一定属于读者当前所在页**。
`show()` 里调 `clearPending()` 作废在飞效果；`after()` 到期时再校验一次当前页（双保险）。

### 根因 C："跳过效果"跳错了地方

`skipPending()` 以前只返回布尔值，调用方一律执行 `next()`。
但摸噜啵（p25）、再读一次（p30）的结局是"回到 p05"，不是"翻到下一页"——
跳过效果反而把读者带去了 p26。

**修法**：`pendingTimers` 存 `{timer, fn}`，`skipPending()` 直接返回该效果本来的结局。

### 根因 D：走回头路时，"已经演出过的效果"不复位

读者会回头重读（p25 摸噜啵、p30 再读一次都会跳回 p05）。
第一轮只复位了**计数**，没复位**页面效果状态**：

| 页 | 状态 | 回头重进后的症状 |
|---|---|---|
| p23 | `is-dim` | 灯还是暗的，点月亮没反应 |
| p19 | `is-bloom` | 彩纸已经是小花，点彩纸没反应 |
| p17 | 螺旋累计角度 | 点一下肚子**直接翻页**（因为角度还停在 360°） |
| p15 | 角色缩放 | 角色还是胖的，"越吃越圆"演不出来 |

**修法**：`BookInteractions.reset(page)` 一并复位页面状态类、螺旋角度与角色缩放
（基准缩放取自模板输出的 `data-base-scale`）。

### 顺带修掉的一处源码损坏

`interactions.js` 里 10 处 `Book.after(...)` 的收尾全部被写成了 `});, page);`
（正确是 `}, page);`）——一次批量编辑把 `);` 插错了位置，整个文件**无法解析**，
`vite build` 直接失败。说明**构建产物与源码可能不同步**，
所以 `tools/check-layout.mjs` 现在会校验 `dist` 产物不比 `src` 旧。

### 本轮新增的断言（冒烟 24 → 35 项）

- 别页的残留计时器不会把当前页翻走；
- 效果没播完就跳过，走效果本来的结局（p05 而不是 p26）；
- p23 / p19 / p15 / p17 回头重进时状态复位。

## 第三轮审查：幼儿乱读（M4 的自动化代理）

M4 原计划是"3 岁孩子试读"。真人物理试读没法在机器上做，但**孩子对这本册子的真实行为是可枚举的**：
乱点、连点、倒着翻、从中间跳着看、拖窗口、乱敲键盘。
这些都能自动化，而且比"大人按顺序点一遍"更容易踩坏状态机。

于是新增 `tools/chaos.mjs`（`npm run chaos`）：用**固定种子的随机数**跑 400 步乱操作
（乱点 / 点热点 / 连点 / 乱划 / 乱敲键盘 / 拖窗口 / 点静音），**每一步**都检查不变量：

- 恰好一页是活动页，且页面 id 合法；
- 最多一个待定效果，且必定属于读者当前所在页；
- DOM 里没有 `undefined` / `NaN` 渗进来，角色 transform、螺旋角度、`data-found` 都是合法值。

跑完再验四件事：乱走之后 p13 / p17 / p27 **仍然能通关**（计数没被搞坏）；
一次点击只翻一页；连点不被吞；从最后一页倒着走能回封面。

它挖出三个真问题（前两个是这轮的收获）：

### 1. 翻页锁把孩子的点击吞掉了（最要命的一个）

以前的翻页锁是"锁住就丢"：

| 操作 | 次数 | 间隔 | 修之前 | 修之后 |
|---|---|---|---|---|
| 空白处连点 | 6 | 150 ms | 前进 **2 页**（4 次被丢） | 前进 **4 页** |
| 空白处连点 | 6 | 250 ms | 前进 3 页 | 前进 5 页 |
| 方向键连按 | 10 | 70 ms | 前进 **2 页**（8 次被丢） | 前进 3 页 |

对 3 岁小孩，"点了没反应"就是"这东西坏了"——他会更用力地戳，
然后更早放弃这本书。

**修法**：节流只限速，不吞输入。最短 350 ms 一页（仍然防止一帧跳两页），
但锁住期间到达的翻页请求会被**记住**，锁一开就补上：
**每个 350 ms 窗口里只要有点击，就翻一页**。不丢、不堆积。

### 2. 排队中的翻页请求会劫持后续导航

`goToId()` 跳到某页后，上一页残留的排队请求还在队列里，
到期后会把读者从刚跳过去的页面又带走一页。

**修法**：把"换页即作废在飞的东西"这条规则补齐——`show()` 里同时清掉排队请求
（和清待定效果是同一条规则的两个分支）。

### 3. 回头重进时效果不复位

已在上一轮修掉（p23 灯变暗 / p19 彩纸开花 / p17 螺旋角度 / p15 角色缩放）。

### 顺带确认的两件事

- **节流不是 bug**：产品设定就是"最短 350 ms 一页"。
  压力测试里"倒着走回封面"这项最初按"每次按键都翻一页"来断言，
  那是测试自己没尊重节流；改成按 380 ms 的节奏按键后通过。
  **判据要和产品的实际设定对齐，不能拿测试的假设当产品的错误。**
- **字体子集要跟着新文案重切**：p04 / p29 换了文案，新增了"腻 声 音 屏 幕 听"等字，
  字符集从 263 涨到 297。不重切的话浏览器会退回系统字体，
  印刷 PDF 里就会混进 SimSun / STKaiti（没授权）。`npm run fonts` 后闸门复核通过 ✓。

只挑**会让用户卡住、绕路、误以为坏了**的问题。

### 用法与前提

- 入口：`dist/index.html`（屏幕互动版，双击即开）、`dist/book.pdf`（印刷版）。
- 核心任务：① 陪孩子把书读完（屏幕版，能点能听）；② 打印一份纸书共读；
  ③ 隔几天再读一次。
- 全程在真实浏览器里操作（Playwright + 桌面浏览器），不是看代码猜的。

### 推翻丢弃的假设（想过、被证伪，不算问题）

| 曾经的怀疑 | 实测结果 | 结论 |
|---|---|---|
| 非当前页还在无障碍树里 / 能被 Tab 到 | `.page { display:none }`，无障碍树与焦点都进不去 | 推翻，丢弃 |
| 中途刷新会回到封面、丢掉进度 | hash 恢复生效，刷新后仍在原页 | 推翻，丢弃 |
| 音效没响，或被浏览器挂起成静音 | AudioContext 状态 `running`；点肚子确实新建振荡器；静音后确实不再发声 | 推翻，丢弃 |
| p13 点鱼/点星"没喂到鱼"是热区错位 | 那是**顺序要求**：得先点苹果，点错顺序本来就该摇头 | 推翻，丢弃 |
| 竖屏手机上书太小是 bug | 正方形书页只能占满宽度，原来那不是"没加载" | 部分推翻；居中仍值得做（低优先级） |
| 印刷版 PDF 在浏览器里会错版 | 32 页、每页 816 px = 216 mm，渲染正确 | 推翻，丢弃 |

### 一条方法上的教训

**"点了没反应"和"点了跳到下一页"，在代码里是同一条分支的两头。**
第一轮我修的是"别乱跳页"，第二轮才想到另一半：多步互动的页面**本来就不该跳**，
而最后一页**本来就没法跳**——两端都得给反馈，规则才是完整的。
这条也是靠"当成新用户去点"才发现的：只审代码时，p30 的 `next()` 早退看起来完全合理。

### 我自己造出来的一个回归，以及它暴露的闸门缺口

修"书页居中"时，我把规则写成 `body.screen { display:flex; align-items:center }`。
可拼版 `proof.html` 的 body 是 **`class="screen static"`**——它也吃到了这条规则，
32 页全被 flex 挤到一起，**整本截图变成白板**。

而当时：

```
npm run check  ✓      结构 / 版式 / 授权 / 字体覆盖 全绿
npm run smoke  ✓      43 项断言全绿
npm run chaos  ✓      乱读压力测试全绿
```

**四道闸门一道都没报**——因为它们量的是结构、版式、交互，不是像素。
只有我打开联系表**用眼睛看**，才发现整本书是空白的。
（截图文件从 198 KB 掉到 8 KB，其实早就有信号，只是没人去看。）

**修法**：`body.screen:not(.static)`，只作用于"互动的屏幕版"。

**补的闸门**：`tools/check-shots.py`（`npm run check:shots`）——
逐页量"不是底色的像素占比"，低于 1% 就算白板。
反向验证过：正常页 63.99% 放行、白板 0.00% 拦下；
现有 32 页的墨迹占比是 3.4%（p04 版权页）~ 82.5%（p14 彩虹页），阈值留了余量。

**教训**：闸门只能保证"它量过的东西"是对的。
**图好不好看，只能靠人看一眼，或者专门给图加一道闸门**——
不能因为"其它检查都过了"就认为产物没问题。

### 一条工具上的教训

`npm run fonts 2>&1 | Select-String ... | Select-Object -First 1` 会**提前掐断管道**，
把还在跑的子集进程砍在半路，字体文件随后才写完——于是产物比源文件旧，
"src 比 dist 新"的闸门报了出来。

跟之前"别用 `Select-String '通过'` 过滤输出"是同一条纪律的另一面：
**别让管道提前结束上游进程**。要省输出就整个跑完再看。

这轮换了个方式挑毛病：拉起一个**独立上下文的对抗审查子代理**，只报"会真的坏掉"的问题；
每一条我自己再复核一遍（复核不过的直接丢掉）。

### 修掉的 8 条

| # | 位置 | 问题 | 修法 |
|---|---|---|---|
| 1 | `src/js/interactions.js` 揉肚子 | **触屏上"画圈揉肚子"完全失效**：触屏拖动不产生 `click`，判定挂在 click 上就永远过不了；`touch-action: manipulation` 还让浏览器拖到一半就发 `pointercancel`，螺旋只转 30° 就断了 | 判定移到 `pointerup`；该热区 `touch-action: none`；手势在文档级收尾 |
