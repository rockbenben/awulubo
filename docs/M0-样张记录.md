## 第二轮：把"绚丽"补上

第一轮出来的是干净的白纸 + 平涂，**不够绚丽**。回头对比参考书（`_analysis/pages_a/`），
它的能量来自三件事，都不是平涂：

1. **笔触本身**：大笔触、边缘毛躁、笔画里有飞白（干笔）。
2. **大色块**：斜向色带、放射线、漩涡、实心圆盘，铺满整页。
3. **大号手写字压在色块上**。

于是新增 `tools/gen-effects.py`：沿中心线生成"笔画"（带宽度变化、两端平切的闭合路径），
再在笔画里嵌几条细的纸白飞白。产物 `src/components/effects.svg`（约 130 KB，确定性可重跑）：

| 符号 | 用途 | 用在哪 |
|---|---|---|
| `prop-rays` | 11 条粗放射线 | p05 魔法时刻、p08 满版红 |
| `prop-rays-tight` | 13 条细放射线 | p06 凑近时的光晕 |
| `prop-swirl` | 一笔画的螺旋色带 | 备用（M1 用） |
| `prop-disc` | 实心圆盘 + 零散飞白 | p07 托着红苹果 |

同色系深浅交替（`--ray` / `--ray2`），纸白飞白用 `--ray-gap`——
红底页上飞白要跟底色一致，否则像划痕。

逐页配色（按语义）：p05 黄＝魔法/兴奋；p06 粉＝甜/友好；p07 蓝盘托红苹果（补色对比）；
p08 满版红 + 深红放射线。拟声词也改成参考书那种**横贯页顶的大字压在色块上**（p05 11u 一行）。

## 第三轮：效果要变，色块要长在页面上

反馈是"为什么一直都是射线"+"一些色块明显分离"。两件事都不是调参数能解决的，是缺一层系统：

### 1. 笔触词汇表（`tools/gen-effects.py` → `src/components/effects.svg`）

| 符号 | 形态 | 特点 |
|---|---|---|
| `fx-rays` | 放射线 | 角色身后的爆发；留给高潮页 |
| `fx-rays-tight` | 细放射线 | 贴着角色的一圈光 |
| `fx-rays-corner` | 角落爆闪 | 从页面一角冲进来，直接冲出画外 |
| `fx-bands` | 斜向色带 | 整页铺满，**不留白岛**（参考书 p11） |
| `fx-swirl` | 漩涡 | 一笔画的粗螺旋（参考书 p03） |
| `fx-disc` | 实心圆盘 | 放大放置即出血压边 |
| `fx-confetti` | 彩纸 96 片 | 位置固定（规格 §7.8），M1 的 S7 用 |

笔画统一由 `ribbon()` 生成：沿中心线、宽度有变化、两端平切；再叠一层**边缘抖动**（`rough`）
做出马克笔的毛边，笔画里嵌细的纸白**飞白**。同色系深浅交替（`--ray` / `--ray2`），
红底页的飞白跟底色一致（`--ray-gap`），否则像划痕。

### 2. 尺寸规则（重排）

- **色块必须出血，不能浮在纸上。** 圆盘放大到 1080 并下移 → 压住下边缘；漩涡出画外；
  色带整页铺满。画外被裁切才是"长在页面上"。
- **角色与色块要有关系**：放射线的圆心对齐角色肚子；漩涡起笔藏在角色身后（`start_deg`）；
  角色压在色块之上。
- **角色占比**：t-dialog 62%（p05）/ 72%（p06，凑近是例外）；t-food 食物 36%；t-color 76%。
- **字**：p05 拟声词 11u 横贯页顶压在色带上（参考书 p05 的做法），其余页拟声词 14–16u。

### 3. 四页各用一种（不重复）

## 第四轮：笔触被切出一条直边

截图上能看到：p06 的漩涡在左边被竖着切掉一块，p08 的放射线在上方被横着切掉一块，
切边是**笔直的**——这正是 bug 的样子（手绘笔触不可能有直边）。

**根因**：`<use>` 引用 `<symbol>` 时会建立一个视口（x / y / width / height），
symbol 里超出视口的内容**被裁掉**。我把效果正好摆在视口边界上：

- p08 `<use href="#fx-rays" x="0" y="180" width="1000" height="1000">` → 视口上沿在 y=180 → 上面的射线被裁 → 横切线；
- p06 `<use href="#fx-swirl" x="220" y="40" …>` → 视口左沿 x=220、上沿 y=40 → 竖切 + 横切；
- p07 的蓝色圆盘同理，只是它的切口被当成了"山丘的形状"，没被当成 bug 看出来。

**修法（根治）**：所有组件从 `<symbol>` 改成 `<g>`，摆放一律用 `transform`。
`<g>` 没有视口，`<use>` 只是克隆，不会裁剪；缩放/位移改用 `translate()` / `scale()`。
角色、道具、笔触三套组件一起改。

顺带修掉两个连带问题：

1. 漩涡内圈半径（120）小于笔宽（124），带状路径自交，甩出一片"叶片"状怪块 →
   内径提到 200、笔宽 52，2.4 圈；
2. `check-pages.mjs` 原来只认 `<symbol id>`，组件换成 `<g>` 后误报"符号不存在" → 改成两种都认。

> 往后放任何会出血的素材（笔触、背景、裁切到画外的图形），都用 `<g>` + `transform`；
> `<symbol>` 只留给"必须自带视口比例"的东西（本项目里已经没有这种用法了）。

## 第五轮：字体授权

要求是"必须用可商用授权的"。核验结果：**现在打进书里的两套字体本来就是可商用的**——
`@fontsource/zcool-kuaile` 与 `@fontsource/lxgw-wenkai` 的 `LICENSE` 原文都写着
"This Font Software is licensed under the SIL Open Font License, Version 1.1"，
且都**没有声明 Reserved Font Name**（OFL 文中出现的只是术语定义，不是保留名声明）。

之前那句"站酷商用授权未确认"来自设计规格里"站酷官网分发条款"的备注；
而本项目用的是 @fontsource（源自 googlefonts/zcool-kuaile）的 OFL 1.1 版本，两回事。

为了不让这条只停在口头，新加**授权闸门** `tools/check-licenses.mjs`（进 `npm run check`）：

- 逐个字体包读 LICENSE，白名单＝OFL 1.1 / OFL 1.0 / Apache-2.0 / MIT；
- 出现"仅供个人使用 / 非商用 / personal use only"等表述 → 失败；
- 声明了保留字体名 → 失败（子集必须改名才能出版）；
- 子集产物缺失 → 失败。

已做过反向验证：塞一个只有 "personal use only" 的假字体包进去，检查确实拦下并返回退出码 1，随后清理。

**一条纪律**：不要从站酷官网手动替换字体文件——官网版条款与 OFL 版不同。

## 相对设计规格的调整

1. **零件外观改为元素内联样式。**
   规格 §7.4 说"CSS 变量控制颜色"，但没说清实现约束：`<use>` 引用后内容落在影子树里，文档 CSS 选择器对影子树不生效。
   所以 `components/*.svg` 里每个零件写成内联 `style="fill:var(--body);stroke:var(--ink);stroke-width:var(--line)"`，
   颜色状态仍由 `.state-red` 等类的 CSS 变量控制（自定义属性能穿透影子树）。页面上的写法不变。

2. **螺旋从姿态里拆出来，单独一行 `<use>`。**
   否则文档 CSS 转不到影子树里的螺旋，"屏幕上慢转"做不了。
   `pose-*` 不含螺旋，页面额外引用 `<use href="#ch-spiral" class="spiral">`。

3. **满版色页：角色身体 = 页面色，靠粗黑线与白色细节撑形。**
   规格 §6.2 只说"正文放在白色手绘底块上"，没定角色怎么办。按参考书 p54 的做法（角色与底色同色、靠黑线定义形状）实现，
   眼白、瞳孔、舌头保持白色/深色对比。p08 实测成立。

4. **印刷版版式提到常规 CSS 层。**
   规格 §8.2 的打印规则原本都写在 `@media print` 里，导致 `print.html` 在屏幕上预览时整页隐藏（无法逐页出图）。
   现在 `body.print .page` 的尺寸规则在常规层，`@media print` 里只留 `@page` 与分页符。

5. **新增 `dist/proof.html`。**
   规格 §9.3 说用 `?static=1` 出图；实际出图走 `proof.html`（body 带 `static` 类），
   页面固定 720 × 720 CSS px，配合 `--dpr 2` 出 1440 × 1440。`?static=1` 仍然可用。

6. **颜色状态里的 `--spiral` 用墨色，不用规格 §7.4 建议的深红。**
   满版红页上深红螺旋会消失在同色身体里。墨色在所有颜色状态下都可读。

7. **新增 `tools/smoke.mjs`（交互冒烟）与 `tools/shots.mjs`（html-shot 封装）。**
   规格 §9.2 只列了"Playwright 冒烟"，本轮先落成可跑的脚本。

8. **新增笔触特效层与颜色令牌。**
   规格 §3.2 提到"黄放射线、红放射线、彩色烟花"是高潮元素，但 §6.6 的七套模板里没有对应位置。
   本轮补了七个笔触符号（见上表），并新增 `--yellow-deep`、`--pink-deep`、`--ray`、`--ray2`、
   `--ray-gap`、`--disc`、`--confetti-*` 共十个令牌。
   规格 §6.2 的"每页最多 3 个填充色"仍成立（p05 黄+深黄+白、黑；p08 红+深红+白、黑）。

## 待用户确认（画风确认点）

1. **角色线条的"手绘感"够不够。** 当前身体是抖动圆（确定性生成），线宽 26（角色占 60% 页高时约 3 mm），
   比参考书略细、略规整。参考书线条更粗更毛躁。要更接近参考书，可加大线宽与抖动。
2. **角色是否够"圆"。** 噜啵目前是一个团子 + 螺旋 + 圆点眼 + 腮红，很干净。
   参考书角色是单眼 + 王冠 + 豆形身体，形态更怪。本项目按规格 §4.3 走"圆身体 + 大嘴 + 螺旋"。
3. **满版色页的同色处理。** 角色与底色同色、只靠黑线分离，是本轮的取舍；另一种做法是角色保留纸白身体、只让页面变色。
4. **手写字体。** 拟声词用站酷快乐体（逐字 ±3° 抖动），旁白用霞鹜文楷。
   参考书全用手写体；当前是"拟声词手写 + 旁白楷体"的分工，旁白是给大人念的，字要清楚。
   （授权已核验：两套都是 SIL OFL 1.1，可商用、可嵌入出版物，见 `LICENSES.md`
   与 `tools/check-licenses.mjs` 闸门。）
5. **笔触层的强度。** 现在的笔画是平涂 + 飞白 + 毛边，接近参考书但更干净；
   若要更接近真实马克笔，可以给同色系再叠一层半透明笔触。
6. **p06 的留白。** 左栏只有两行字、右侧一个凑近的角色，留白约 55%。是否需要再加一点信息（例：一个小道具）？

## 第二轮审查（交互状态机，2026-10-30 续）

第一轮只覆盖了"闸门与结构"，没深挖交互状态机。这轮实测出 **7 处真 bug**，
其中 4 处是同一个根因的不同表现。

### 根因 A：`page` 传成了 DOM 元素，`pageId` 当字符串用

`interactions.js` 里 10 处 `Book.after(750, fn, page)` 传的是**页面元素**，
`book.js` 的 `after(ms, fn, pageId)` 却把第三个参数当 **id 字符串**用。
于是所有页面的计时器键都退化成同一个 `"[object HTMLDivElement]"`：

- "这一页的效果"和"别页的效果"分不开 → 上一页的计时器会吃掉下一页的点击；
- 计时器到期时执行 `Book.next()`，翻的是**读者当前所在页**，不是这个效果该去的页 →
  p15 的残留计时器把读者从 p25 翻成了 p26；
- 修第一版时又踩了一次：加"到期时校验当前页"的守卫，因为键是脏的，**所有效果都被丢弃**，
  点肚子不翻页了。

**修法**：`book.js` 里加 `pageKey()` 统一归一化（元素或 id 都接受），
参数类型不认识时**直接抛错**，不再静默合并成一个键。

### 根因 B：换页不作废在飞效果

`show()` 只换页，不清上一页还在计时的效果。读者离开一页后，那个"翻页"还在跑；
等他回头再进那一页，计时器到期会把他莫名翻走。

**修法**：确立不变量——**任一时刻最多只有一个待定效果，且它一定属于读者当前所在页**。
`show()` 里调 `clearPending()` 作废在飞效果；`after()` 到期时再校验一次当前页（双保险）。

### 根因 C："跳过效果"跳错了地方

`skipPending()` 以前只返回布尔值，调用方一律执行 `next()`。
但摸噜啵（p25）、再读一次（p30）的结局是"回到 p05"，不是"翻到下一页"——
跳过效果反而把读者带去了 p26。

**修法**：`pendingTimers` 存 `{timer, fn}`，`skipPending()` 直接返回该效果本来的结局。

### 根因 D：走回头路时，"已经演出过的效果"不复位

读者会回头重读（p25 摸噜啵、p30 再读一次都会跳回 p05）。
第一轮只复位了**计数**，没复位**页面效果状态**：

| 页 | 状态 | 回头重进后的症状 |
|---|---|---|
| p23 | `is-dim` | 灯还是暗的，点月亮没反应 |
| p19 | `is-bloom` | 彩纸已经是小花，点彩纸没反应 |
| p17 | 螺旋累计角度 | 点一下肚子**直接翻页**（因为角度还停在 360°） |
| p15 | 角色缩放 | 角色还是胖的，"越吃越圆"演不出来 |

**修法**：`BookInteractions.reset(page)` 一并复位页面状态类、螺旋角度与角色缩放
（基准缩放取自模板输出的 `data-base-scale`）。

### 顺带修掉的一处源码损坏

`interactions.js` 里 10 处 `Book.after(...)` 的收尾全部被写成了 `});, page);`
（正确是 `}, page);`）——一次批量编辑把 `);` 插错了位置，整个文件**无法解析**，
`vite build` 直接失败。说明**构建产物与源码可能不同步**，
所以 `tools/check-layout.mjs` 现在会校验 `dist` 产物不比 `src` 旧。

### 本轮新增的断言（冒烟 24 → 35 项）

- 别页的残留计时器不会把当前页翻走；
- 效果没播完就跳过，走效果本来的结局（p05 而不是 p26）；
- p23 / p19 / p15 / p17 回头重进时状态复位。

## 第三轮审查：幼儿乱读（M4 的自动化代理）

M4 原计划是"3 岁孩子试读"。真人物理试读没法在机器上做，但**孩子对这本册子的真实行为是可枚举的**：
乱点、连点、倒着翻、从中间跳着看、拖窗口、乱敲键盘。
这些都能自动化，而且比"大人按顺序点一遍"更容易踩坏状态机。

于是新增 `tools/chaos.mjs`（`npm run chaos`）：用**固定种子的随机数**跑 400 步乱操作
（乱点 / 点热点 / 连点 / 乱划 / 乱敲键盘 / 拖窗口 / 点静音），**每一步**都检查不变量：

- 恰好一页是活动页，且页面 id 合法；
- 最多一个待定效果，且必定属于读者当前所在页；
- DOM 里没有 `undefined` / `NaN` 渗进来，角色 transform、螺旋角度、`data-found` 都是合法值。

跑完再验四件事：乱走之后 p13 / p17 / p27 **仍然能通关**（计数没被搞坏）；
一次点击只翻一页；连点不被吞；从最后一页倒着走能回封面。

它挖出三个真问题（前两个是这轮的收获）：

### 1. 翻页锁把孩子的点击吞掉了（最要命的一个）

以前的翻页锁是"锁住就丢"：

| 操作 | 次数 | 间隔 | 修之前 | 修之后 |
|---|---|---|---|---|
| 空白处连点 | 6 | 150 ms | 前进 **2 页**（4 次被丢） | 前进 **4 页** |
| 空白处连点 | 6 | 250 ms | 前进 3 页 | 前进 5 页 |
| 方向键连按 | 10 | 70 ms | 前进 **2 页**（8 次被丢） | 前进 3 页 |

对 3 岁小孩，"点了没反应"就是"这东西坏了"——他会更用力地戳，
然后更早放弃这本书。

**修法**：节流只限速，不吞输入。最短 350 ms 一页（仍然防止一帧跳两页），
但锁住期间到达的翻页请求会被**记住**，锁一开就补上：
**每个 350 ms 窗口里只要有点击，就翻一页**。不丢、不堆积。

### 2. 排队中的翻页请求会劫持后续导航

`goToId()` 跳到某页后，上一页残留的排队请求还在队列里，
到期后会把读者从刚跳过去的页面又带走一页。

**修法**：把"换页即作废在飞的东西"这条规则补齐——`show()` 里同时清掉排队请求
（和清待定效果是同一条规则的两个分支）。

### 3. 回头重进时效果不复位

已在上一轮修掉（p23 灯变暗 / p19 彩纸开花 / p17 螺旋角度 / p15 角色缩放）。

### 顺带确认的两件事

- **节流不是 bug**：产品设定就是"最短 350 ms 一页"。
  压力测试里"倒着走回封面"这项最初按"每次按键都翻一页"来断言，
  那是测试自己没尊重节流；改成按 380 ms 的节奏按键后通过。
  **判据要和产品的实际设定对齐，不能拿测试的假设当产品的错误。**
- **字体子集要跟着新文案重切**：p04 / p29 换了文案，新增了"腻 声 音 屏 幕 听"等字，
  字符集从 263 涨到 297。不重切的话浏览器会退回系统字体，
  印刷 PDF 里就会混进 SimSun / STKaiti（没授权）。`npm run fonts` 后闸门复核通过 ✓。

### 我自己造出来的一个回归，以及它暴露的闸门缺口

修"书页居中"时，我把规则写成 `body.screen { display:flex; align-items:center }`。
可拼版 `proof.html` 的 body 是 **`class="screen static"`**——它也吃到了这条规则，
32 页全被 flex 挤到一起，**整本截图变成白板**。

而当时：

```
npm run check  ✓      结构 / 版式 / 授权 / 字体覆盖 全绿
npm run smoke  ✓      43 项断言全绿
npm run chaos  ✓      乱读压力测试全绿
```

**四道闸门一道都没报**——因为它们量的是结构、版式、交互，不是像素。
只有我打开联系表**用眼睛看**，才发现整本书是空白的。
（截图文件从 198 KB 掉到 8 KB，其实早就有信号，只是没人去看。）

**修法**：`body.screen:not(.static)`，只作用于"互动的屏幕版"。

**补的闸门**：`tools/check-shots.py`（`npm run check:shots`）——
逐页量"不是底色的像素占比"，低于 1% 就算白板。

**教训**：闸门只能保证"它量过的东西"是对的。
**图好不好看，只能靠人看一眼，或者专门给图加一道闸门**——
不能因为"其它检查都过了"就认为产物没问题。

### 二、背景为什么没自动全局

用户问「html 背景现在为什么没自动全局」。先量了一遍：
把每页截图的边缘带取出来，看有多少比例不是纸白——

| 结果 | 页 |
|---|---|
| 铺满 | 11 页 |
| 没铺满 | 16 页（p03/p06/p07/p09/p11/p13/p15/p16/p17/p18/p19/p22/p25/p27/p28/p30） |

翻渲染器才看清根因：`viewBackground()` 用「焦点到最远角的距离 ÷ 特效半径」算放大倍数，
这等于**假设每个特效都是一块居中的圆盘**。实际不是：

- `fx-swirl` 是环（r 200–600），里面空着；
- `fx-confetti` / `fx-sprinkle` 是散点，本来就盖不满；
- `fx-rays-corner` 的圆心在页外角（-40, 1040），从页外冲进来；
- `fx-rays` 的 11 根射线在页边只有约 26% 的角覆盖率——就算半径够，也是「几根条子」不是满版。

所以**放大倍数再大也盖不满**：16 页的色块是浮在白纸上的孤岛（用户早前说的
「色块不能是浮在白纸上的孤立色块，要长在页面上」）。
另外 `EFFECT_RADIUS` 这张半径表在 `gen-effects.py` 与 `render-page.mjs` 里**各写了一份**，
改图形忘了改表就会按错的半径算。

### 改法：背景分两层

1. **满版底色场**（新组件 `fx-wash`）：一块毛边色块，半径 900 > 页面对角线的一半（707），
   所以「铺满整页含出血」是**几何保证**，不靠放大倍数凑。
   每页在数据里声明 `bg.wash`（用哪个色板令牌），淡色底子留得住黑字，笔触才跳得出来。
2. **笔触**：照旧，但几何改成由 `src/components/effects.json` 驱动——
   `gen-effects.py` 生成图形时**顺手生成几何表**，两边不再各写一份。

底色场用淡色（`--wash-*`），高潮页（红/蓝/黄/彩虹/夜）用满色，笔触与底色同族、靠飞白分层次。
结果：整本读起来像一本满版色书，只留三张纸页（前环衬、给大人的话、后环衬）。

### 三、闸门（两道新的）

- `tools/check-shots.py` 加了「背景铺满」：声明了底色场的页，四条边的**主色**不能还是纸白。
  这里踩过一个坑：第一版量的是「边上有没有非白像素」，结果 p07/p09/p11/p30 **误报**——
  角色的身体是纸白的，常常压在页边。改成量「主色」才准。
- `tools/check-contrast.mjs`（新）：按**真实像素**量文字底下是什么颜色，再算 WCAG 对比度。
  正文 ≥ 4.5:1、大字 ≥ 3:1。
  同样踩了坑：第一版按页面底色算，p08 的旁白误报——它其实落在白色气泡上；
  改成取「墨迹紧包围盒」里的底色、并剔掉抗锯齿光晕，才是真值。

### 五、这轮的教训

- **「自动」是有承诺的**：渲染器的注释写着「保证笔触布满全局并溢出出血」，
  但实现只对少数几种笔触成立。注释里的承诺要么实现，要么删掉。
- **闸门要量对对象**：量「像素非白」和量「页面底色」，都会把前景（角色、气泡）算成背景。
  量几何（SVG 包围盒）或量主色，才不会被前景带偏。

## 第七轮：除了吃，还有什么好玩

用户问了两件事：**「角色只有吃的吗，还有没有什么好玩的」**，以及要一份
**能自己在家印出来的双面小书**。这一轮把三件都做了。

### 一、拍一拍：点角色就有反应

原来的规则是"点哪儿都翻页"，只有喂食那几页点中主角才有反应——
**孩子最先戳的那个东西，在其余 28 页里毫无反应**。

现在：**点在噜啵身上，它晃一下、叫一声，然后照样翻页。**

- 不逐页摆热区：用 `event.target.closest('.char')` 判断点到的是不是角色。
  热区是要靠猜角色可见框的（"道具的锚点 ≠ 可见中心"那个坑），
  而事件目标直接告诉我们点在谁身上。
- 翻页照旧：点了有反应、页也翻了，孩子不会觉得卡住。
  `trap` 页（要点好几下才过的那些）不触发——那些页在等一个特定动作。
- 角色自己就是互动目标的那页（摸噜啵那张脸）不算，它归原来的动作。

### 二、两个新跨页：躲猫猫 + 数一数

**页数必须是 4 的倍数**（骑马钉），所以只能一次加 4 页：加一个跨页是 34 页，
排不出帖。两个跨页 → 36 页 ✓。

**p29–p30 躲猫猫**（参考书的"咦？不见了"）：
左边"咦？噜啵去哪儿了？"，右边它从苹果后面探出来"找到我啦！"——
翻过去就找到了，纸上完全成立。右边那页的动作就是**拍一拍**，
新机关在这一页变成了故事的一拍，不只是"多一个功能"。

**p31–p32 数一数**：三个红苹果，点一个，旁边的数字冒出来；数满三个才翻页。
这是书里第一个"要数东西"的页，数数是 3–5 岁最该练的本事之一。

两处踩过的坑：

- **数字不能用站酷快乐体**：它的「3」写成了「三」的样子，
  数数页上「一」和「1」混在一起，孩子学的是阿拉伯数字，不是汉字 → 改用霞鹜文楷。
- **数字一开始是藏着的**：靠 `.number.is-on` 显形，互动里点亮对应的那个；
  进页要复位，否则回头重进时数字已经全亮，一碰就翻页。

### 三、页码整体后移

新跨页插在中间，后面的页码全部往后挪：

### 四、A4/A3 双面骑马钉拼版

给家用打印的版本：一张 A4 横放，每个面并排两个书页，**双面打印后沿中缝对折，
中间订一下就是一本**。

- 页序按骑马钉排：最外一张是封面与封底，往里依次往中间收。
- A4 版成品 148.5 × 148.5 mm（缩到 69%）；A3 版成品 210 × 210 mm（不缩）。

## 第十一轮：噜啵的行为谱系（1+2+3）

用户说「角色只有吃的吗，还有没有什么好玩的」，挑了三件：
**它发现你**、**兑现飞行伏笔**、**亲子动作页**。

### 先想清楚页数：为什么是 44 页不是 42

新内容按 2 页一个跨页进来，36 + 6 = 42，**42 不是 4 的倍数，骑马钉排不出帖**（双面打印时书脊那帖会缺一面）。
所以要么 44（多一个跨页），要么 40（少一个）。

最后选了 **44 页**（4 个新跨页），理由是**每页一件事**这条书自己的规矩：
三个亲子动作（拍手/转圈/跺脚）各占一个跨页，
而不是把三个动作塞进一页——塞进一页就分不清哪个泡对应哪个动作，
而且违反"每页只做一件事"。

### 飞行：不另起一页，就地兑现

「彩纸把噜啵卷起来，送到天上啦！」（p20）这句话一直没人兑现——
p21 玩累了、p23 晚安、p25 第二天，承诺越拖越远。
所以飞行**不占新跨页**：就在 p20 上，点它，它横着飞过天空（呼——）。
承诺与兑现隔得越近，孩子越接得住。

### 动画怎么写：改 SVG 属性，不碰 CSS transform

角色位置写在 SVG 的 `transform` 属性上（`translate(x,y) scale(s)`）。
**CSS 的 transform 一设就把那个属性整个顶掉，角色会跳回原点**——
`book.css` 里数数那页的注释早就写过这条（道具用 `translate` 而不是 `transform` 动画）。

所以飞、转圈、跺脚都是逐帧改**属性**本身：

```
translate(x,y) scale(s) rotate(deg, cx, cy)
```

`rotate` 的第三、四个参数是旋转中心——必须用角色自己的中心（`getBBox()` 量），
绕页面原点转会把角色甩到角落里。
`getBBox()` 在页面隐藏时会抛，所以取中心要包 try。

回头再进这一页要复位：渲染器把原始位置写在 `data-base-transform` 上，`reset()` 照它放回去。
不复位的话，第二次进来角色还停在"飞到一半"的地方，看着像坏了。

### 两条新闸门（原来漏了角色）

`check-layout.mjs` 以前只查**道具**热区（`class` 以 `prop-` 开头），
**角色热区没人管**——p25「摸摸噜啵」当初就栽在这：热区压在角色上方空处，点它的脸点不到，
而闸门全绿。现在补了三条：

1. 角色的热区必须罩住角色中心；
2. 角色不能被页面**左右**边缘裁掉（p40 的角色被切出一条竖直直边，像被门夹了一下）；
3. 上下出血不算错——p07/p09/p11 那三页"喂东西"是特写，角色大到出画，
   读起来是"凑得很近"；左右出血才算错。

> 新闸门要有牙齿才算闸门：写完先**故意把 p34 的热区挪歪**，
> 确认它报错（"角色中心在 711,628"），再改回去。

### 顺带修掉的三个真缺陷

- **p40 角色被右边缘切掉**（可见框到 x=1028）——新闸门抓到的。

# 第十三轮记录：第二册《噜啵生病啦！》

## 第二册不是第一册拉长

第一册是**孩子喂它**，第二册把孩子的角色翻过来：**孩子照顾它**。

| | 第一册《啊呜噜啵！》 | 第二册《噜啵生病啦！》 |

| 副标题 | 一个要你**喂**的小怪物 | 一个要你**照顾**的小怪物 |
| 四幕 | 它躲猫猫 → 你喂它 → 它把颜色送给你 → 玩够啦 | 它今天不对劲 → 我来照顾你 → 等它好起来 → 它好了 |
| 高点① | p21–22（33%）彩纸喷发 | p21–22（34%）药太苦，它的脸皱成一团 |
| 高点② | p47–48（74%）颜色都送给你 | p47–48（74%）一起跑、一起跳 |
| 尾巴 | 玩累了 → 晚安 → 明天见 | 玩累了 → 晚安 → 它的呼噜声 → 明天见 |

新增道具 4 件（毯子 / 水杯 / 药丸 / 睡着的 z）、新增姿态 2 个（`ouch` 难受 / `grumpy` 不高兴）、
新增互动 4 个（盖毯子 / 喂水 / 喂药 / 半夜咳嗽）。

⚠️ **`ouch` 第一版画成了怒眉。** 第一册踩过一遍的坑：
「眉毛里端往下」是**生气**，不是难受（`shy` 与 `tired` 就被画成了怒眉）。
难受要用 `ch-brows-worried`（里端往上），眼睛还得挤起来才像「皱成一团」——
圆眼睛配那张脸读起来是发愣。于是拆成两个姿态：
`ouch`（难受：眉头往里拧 + 眼睛挤起来）用在发烧与药太苦，
`grumpy`（不高兴：眉里端往下）用在它不喝水、不吃药。

## 色彩脚本：与第一册相反的走法

第一册是**暖 → 彩 → 静**；第二册是**冷 → 柔 → 夜 → 暖**：
开篇的蓝与紫（它不对劲）→ 粉与黄（守着它）→ 夜（半夜咳了一声）→
最后它好了，红与橙才回来。

⚠️ **照顾它的那几页不能用橙红。** 一本讲「照顾一个生病的朋友」的书，
满页橙红读起来像着急，不像屋里守夜——第一版把 p13–p26 全刷成橙红，
改回粉/紫/黄之后才读成「夜里陪着一个人」。

## 页码在册内独立，把几道闸门一起骗了

两册的页码各自从 p01 开始，于是同一个 `p05` 在两册里指两页。
闸门原来用 `querySelector('[data-id="p05"]')` 找页面——**永远只找得到第一册那页**，
然后拿第一册的结果去汇报第二册：

- 热区检查、版式检查、对比度检查：改成按 `[data-id][data-book]` 定位，
  跳转时也带册 id（`Book.goToId(id, book)`）
- 截图：每册一个子目录（`dist/shots/<册 id>/pXX.png`）——两册都有 p01，
  同一个文件名装不下两页
- 选页器：只列**当前册**的 60 页，换册要重建格子（里面是上一册的缩略图）

⚠️ 还有一个更隐蔽的：**「越吃越圆」原来按页码判断**（`data-id === 'p17'`）。
第二册也有一页叫 p17（喂水），按页码判会把它当成「越吃越圆」那一页——
喂一口就退回去，孩子永远过不去。现在判据改成**页面上有没有 `#grow-char`**。

# 第十四轮记录：网页版摊开成跨页 / 稿子按 3 岁重写一遍

日期：2026-11-01 ｜ 起因：把书**打开**看了一遍，发现两件事

## 网页版是翻书，不该一页一页放

以前的网页版一次只给一页——那不是翻书，是看幻灯片。屏幕够宽时应该摊开成
**左右两页**，翻一次翻一跨。

**哪两页对在一起不能自己定。** 骑马钉的书永远翻到「偶数页 | 奇数页」：
封面 p1 是单页，往后 (p2|p3)、(p4|p5)……（`tools/vite-pages.mjs` 的
`bookletSheets` 就是这么排的）。纸书翻开来是哪两页，网页就得是哪两页——
同一段故事，屏幕上一屏两页、纸上一翻两页，孩子看到的才是一样的翻法。

| | |
|---|---|
| 分组 | `book.js` 的 `buildSpreads`：偶数页且下一页正好是 +1 就并成一跨；屏幕版跳过的那几页（版权页、给大人的话……）不在跨页里，搭档独自成页 |
| 摆开 | `book.css` 的 `@media (min-width: 1100px)`：每页占一半屏宽，中间一道书脊阴影 |
| 断点 | 1100px。每页只占一半屏宽，字也小一半：1100px 时每页 550px，正文 3.4% 的字高约 19px；再窄就一页一屏（手机上两页字太小） |
| 页码 | 跨页时显示范围：「8–9/60」 |
| 翻页 | 宽屏翻一跨，窄屏翻一页 |

⚠️ **断点写了两遍**（CSS 的媒体查询 + JS 的 `SPREAD_QUERY`）：两边不一致时，
屏幕上摊着两页、翻页却只走一页——很难看出来，只能靠翻页的手感发现。

⚠️ **「点空白不翻页」要按整组算**：这一跨里有一页在等一个动作（`trap`），
点另一页的空白也不能翻过去，否则孩子能靠点旁边那页把要互动的一页跳过去。

⚠️ **效果可能演在右页上**：跨页时 `current` 记的是左页，拿 `current` 去比
「这个效果是不是过期了」会把右页的效果当成过期的丢掉——右页的互动就永远演不完。

## 稿子按 3 岁的耳朵重写一遍

把两册 56 个跨页逐个按三个问题过一遍：**能理解吗 / 能接受吗 / 愿意互动吗。**
改掉的都是三岁孩子不认识的词，和图字对不上的地方：

| 册 | 页 | 原来 | 改成 | 为什么 |
|---|---|---|---|---|
| 二 | p15 | 端一杯来 | 拿杯水来 | 「端」是大人端的词 |
| 二 | p16 | 再劝劝它 | 再叫叫它 | 「劝」三岁不认得 |
| 二 | p17 | 不然好不了 | 不然不会好 | 「好不了」是缩略，孩子接不住 |
| 二 | p19 | 最难的一关 | 喂它吃药 | 「一关」是游戏比喻，孩子只会想到关门 |
| 二 | p23 | 像哄小孩子那样 | 轻轻地拍 | 「哄」太难；而且这一页的动作本来就是拍 |
| 二 | p32 | 睡得比昨天沉 | 睡得比昨天香 | 「沉」是抽象词，「香」是孩子会用的 |
| 二 | p35 | 它饿了会说的（连说三遍） | 拿一个苹果来 / 让它闻闻 | 同一句在三页里出现三次，听着像卡带 |
| 二 | p12 | 书上说的…… | 让我想想…… | 三岁孩子不读书，这话没有出处 |
| 二 | p21 | 一张笑脸 + 「怎么这张脸？」 | 脸改成 `ouch` | 图和字对不上：孩子问"脸怎么了"，画上却没事 |
| 一 | p19 / p21 | 两页都写「揉一揉，顺一顺。」 | p21 改成「转个圈，」「在噜啵的肚子上画圈。」 | 同上：抄两遍像卡带 |

顺带把「一关」「沉」「哄」「劝」这些词的规矩写进了设计规格 §5.3.1：
**能理解 / 能接受 / 愿意互动**，三条硬标准，写完一段问一遍。

## 这一轮的账

| 项 | 之前 | 之后 |

# 第十五轮记录：跨页的左右两页，得是一件事

日期：2026-11-01 ｜ 起因：翻开书，点左边那一页，书却把这一跨翻过去了；
而且摊开的两页常常是两个不相干的颜色

## 先查出来的不是颜色，是页号

两个毛病，根子是同一个。

骑马钉的书永远翻到「偶数页 | 奇数页」：封面 p1 单页，往后 (p2|p3)、(p4|p5)……
而页面数据是按「一个文件 = 一个跨页」写的，每份文件从**奇数**页起——
版权页占着 p4，正文从 p5 起。于是每份文件的两页分落在两跨里：

```
文件 A: p5  p6      屏幕上摊开的是 (p4|p5)、(p6|p7)
文件 B: p7  p8      → 左页是上一场的右页，右页是下一场的左页
```

每一跨都错开一页。第一册「你叫什么名字呀」的右页，对的是「先吃一个红苹果」的左页；
两页各说各的，颜色当然也各是各的。**这不是配色问题，是装订问题。**

页数、字数、版式、热区四道闸门当时全绿——它们量的都是**单页**。
单页怎么量都量不出「谁跟谁对在一起」。

## 修法：版权页移到书末

中文书的版权页本来就在最后。前置页从 4 页变 3 页（封面 / 前环衬 / 扉页），
版权页挪到 p60，正文 p4–p59，后置 5 页（版权页 / 给大人的话 / 再读一次 / 后环衬 / 封底）。

- 没有新增内容，没有丢内容，两册仍然各 64 页、屏幕版各 60 页
- 30 份页面数据文件全部改名减一（`05-hungry.js` → `04-hungry.js`，……）
- 屏幕版跳过的四页变成 p60 / p61 / p63 / p64

**新闸门**：`tools/check-pages.mjs --full` 现在要求**同一跨的两页来自同一个文件**。
写完先弄坏一次验证它会红——把 p04 挪回前置页，它报：
「p4|p5 这一跨的两页来自不同文件（01-front.js / 04-hungry.js）」。

## 点哪一边，往哪边走

摊开时左边是**刚读过的那页**，右边是**还没读的那页**。以前不分左右，点哪儿都往前——
孩子想回头看左页，书却把这一跨翻过去了。现在点右页往前、点左页往回，
跟翻纸书一样；点在书页之外（上下留白、舞台两侧）仍算往前，那是「继续」的意思。

冒烟补了两条断言：点左页回到上一跨、点右页进到下一跨。

## 一跨一个色系

配对修好之后，剩下的才是配色：一跨的两页共用一套底色场——
同样的 `colors` / `gap` / `wash`，放射线、漩涡的圆心对着书脊，
左右各露一半，翻开来是**一幅画**。

- **19 跨**把圆心挪到书脊（左页 `focus: [1000, y]`、右页 `focus: [0, y]`）
- **29 跨**把右页的色板并到左页（`kind` 与 `focus` 保留，只统一颜色）
- **7 跨**保留换色——正文自己宣告了转折：变红 / 变蓝 / 变黄 / 彩虹 / 药太苦 /
  它病了 / 颜色要回家了。这几跨的右页是左页的**结果**，孩子读到的是因果，
  不是两张不相干的图

换色时踩到一个坑：统一色板顺手把右页的 `gap` 也抄成了左页的 `--red`，
满版红上压黑字只剩 4.3:1，「你瞧我！」整句发虚。对比度闸门逮住了它——
右页的 `gap` 要留纸白（`--paper`），放射线的缝才压得住字。

另外两跨（第二册 p8 / p22）的「呼……」压在深紫笔触上只有 2.2:1，
垫了一块手绘白底块（`prop-blob-white`，同第一册 p12 / p46 的手法）。

## 顺带：`npm run pdf` 真的每册一本了

清单里写着「`npm run pdf` 产出 64 页 PDF（每册一本）」，但命令写死了
`dist/book.pdf`——跑一次只印一册，还把上一册覆盖掉。现在按册清单逐册导出

# 第十七轮记录：一跨两页，左页的互动不许把右页一起带走

## 先查出来的：闸门全绿，故事少了两拍

翻书的样子做出来以后（第十五轮），一直没细看**跨页里的互动**是怎么走的。
这一轮去看，发现四跨里少了东西：

| 跨页 | 左页 | 右页 | 实际发生的 |
|---|---|---|---|
| p16 \| p17 | 连喂三口（越吃越圆） | 点它的肚子，咕噜 | 喂饱 → 整跨翻到 p18 \| p19，**咕噜没了** |
| p22 \| p23 | 点彩纸 | 看它飞过去 | 彩纸演完 → 整跨翻到 p24 \| p25，**飞也没了** |
| p44 \| p45 | 拍一拍角色 | 我看见你啦 | 拍完 → 整跨翻到 p46 \| p47，**「我看见你啦」被顺走** |
| p04 \| p05 | 点肚子，咕噜 | （无） | 拍角色 → 整跨翻走，**咕噜没了** |

原因很直白：动作演完调的是 `Book.next()`，而**跨页模式里 `next()` 翻的是一整跨**。
互动是「一页」的意思，翻页是「一跨」的意思，两个单位撞在一起，右页那一拍就没了。

## 修法：整组都好了才翻

- `Book.isDone(page)`：一页没有动作 → 天生是好的；有动作 → 等它演完（`data-done="1"`）
- `Book.finish(page)`：动作演完 → 给这一页写上 `data-done`，再看整组
- `Book.turnIfDone()`：**整组都好了才翻**；单页模式下一组就一页，行为跟从前一样
- `BookInteractions.reset()` 顺手把 `data-done` 清掉（读者会走回头路）

拍一拍（点角色）也走 `turnIfDone()`：它是「这一页没有要做的事」，
不代表「旁边那一页的事也做完了」。

## 顺带定下来的一条：往回走不受 trap 拦

`trap`（点空白不翻页）拦的是**往前**。往回走不算跳过这一页——孩子还会回来。
但点在**正在等动作的那一页**上时不往回走：那是点空了，该摇一下头；
往回走反而把孩子带离任务，前面攒的进度也会被清掉。
（现在每一跨的 trap 页都在左边，所以这一条实际的效果是：
trap 跨上点左页是摇一下头，点右页也是摇一下头；往回走用滑动或方向键。）

## 这一轮为什么闸门没拦住

`npm run smoke` 的主断言跑在 **900px** 视口上——那是单页模式，
一页一屏，一页一页翻。跨页那一段（1440px）只量了「摊不摊开」「翻一跨」「点哪边往哪边走」，
**一条互动的量都没有**。所以这个毛病能在全套闸门绿着的情况下活好几天。

补上的断言（都在宽屏那一段里）：

- p16 喂满三口后**这一跨还在**；p17 的咕噜演完才翻到下一跨
- p22 的彩纸演完**这一跨还在**；p23 飞过去之后才翻到下一跨
- 拍一拍 p44 **不会把 p45 的互动一起带走**；p45 演完才翻到下一跨
- p14 \| p15 在等动作时点空白不动

**牙齿验证**（AGENTS §6 第 11 条）：把 `turnIfDone` 里那句
`if (groupPending()) return;` 去掉 → 上面三条断言立刻变红
（"p16 喂满三口后这一跨还在（实际 p18 + p19）"），改回去又全绿。

## 这一轮的账

| 项 | 之前 | 之后 |
|---|---|---|
| 动作演完 | 直接 `next()`（跨页里翻一整跨） | `finish(page)` → 整组都好了才翻 |
| 跨页里的互动 | 冒烟没量过 | 宽屏那段量四条（喂三口 / 彩纸 / 拍一拍 / trap） |
| 冒烟断言数 | 105 | **114** |
| 点左页 | 被 trap 拦成「摇一下头」 | 往回走放行；trap 页本身仍是摇一下头 |

# 第十八轮记录：门面图不许拿旧构建来拍

## 查出来的：脚本不保证图是「当前构建」的

`npm run shots:readme` 只检查 `dist/index.html` 在不在——**在**就拍。
可它不检查这个 `dist/` 是不是当前的：改了页面数据、忘了重新构建，
脚本就拿**上一次**的构建拍出一套图，而且拍得出来、看不出来：
画面几乎一模一样（差的是边缘的抗锯齿），可它拍的不是现在的页面。

README 的图是仓库里最先过期的东西（这一版 README 自己写着这句话），
所以这道闸门得由脚本自己保证，不能靠人记得先跑构建。

## 改法

`tools/readme-shots.mjs` 现在比时间戳：`dist/index.html` 比源码旧就停下报错。
⚠️ 比的是**目录里最新的那个文件**，不是目录自己的时间戳——
目录时间戳只在增删文件时才变，改文件内容不会动它，拿它去比等于闸门永远是开的
（第一版就写错了：touch 一下源文件，闸门照样放行）。

## 顺带量到的一件事：门面图不是「逐字节可复现」的

同一台机器上连跑两次 → 完全一样（0 个像素差）。
换一台机器重拍 → 差 0.006% 的像素（都是边缘的抗锯齿，最大差 81/255）。
所以「图过期了」的判据不是字节相同，而是**拍的是不是当前构建**——
这正是上面那道闸门管的事。

## 这一轮的账

| 项 | 之前 | 之后 |
|---|---|---|
| `npm run shots:readme` | `dist/` 在就拍，可能是旧构建 | 产物比源码旧 → 报错停下 |
| `npm run check:shots` | —— | 128 张都有内容（墨迹 4.1% ~ 82.4%） |
| `npm run pdf` | —— | 每册一本 64 页，字体只有自己那两套子集 |
