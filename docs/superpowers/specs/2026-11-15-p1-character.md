## 依赖与本轮范围

P0-1五册R7已确认冻结，P0-2共320页状态已完整复核。当前逐字附件、状态清单和对象身份账本齐全，可开始共用角色能力建设。本轮只建设SVG角色零件、组合姿态、表情与穿戴锚点，维护渲染和品牌生成，补专项回归及组件校样。不改五份R7原稿、状态附件、书稿数据、场景或动作处理器，不进入P1-2、P1-3或P2整册迁移。

## 已确认的根因与处理

实际旧库多数pose引用ch-arm零件，品牌生成器也直接展开手臂；这与冻结R7的无手设定冲突。先加入专项回归，在修改组件前执行时稳定报“无手角色的姿态仍引用了手臂”，再移除可见引用。25个既有pose ID继续存在；四个旧手臂ID保留为空兼容占位，不再有路径，cheer／wave等旧名称也不再表示有手。

旧正文暂不改成R7，但现有角色会立即变为无手。这是本阶段对共享设定的修正，不是将旧剧情的所有动作自动迁移正确；仍须在P1-3和P2分别对齐动作分类与整册事件。品牌生成器同步使用无手零件，并按既有命令重建logo、社交预览和README截图，避免门面仍显示手臂。

## 新增共用能力

身体轮廓继续复用原手绘线，身体坐标中的形变与页面定位分开；脚型有接地、跨步、单脚悬起、趴伏后脚、收拢及鼓球时双脚抬起。表情用眼睛注视、眉和嘴组合：自主张嘴、犹豫闭嘴、绷紧、放软休息及单眼侧脸均有独立可复用零件，不给衣物绑定情绪变化。

| 组合pose ID | 本阶段可提供的状态 | 后续使用边界 |
|---|---|---|
| ready | 站稳等候，闭嘴温和 | 等待不是强制点击 |
| willing | 朝一侧看、先自主张开小口 | 可承载愿喝信号；杯距与饮水先后仍由书稿和后续制作决定 |
| hesitant | 注视一侧、嘴闭、眉犹豫 | 不把犹豫自动判定为愿意或生气 |
| braced | 身体竖长、脚接地、眉嘴绷紧 | 不以满版换色代替身体张力 |
| step | 跨步脚型与前进准备 | 路线、位移和终点留待动作映射 |
| poised | 一脚接地、一脚抬起，目光看向孩子侧 | 悬脚不等于已经碰物；具体星的位置不在本轮制作 |
| yield | 身体回收、步态承接退让 | 后续必须真实挪开并让出通路，不能只换表情 |
| push | 压低身体与侧脸，脚支撑 | 物件接触及结果落点由后续逐页制作负责，不新增手 |
| prone | 身体明显压低、后脚露出、休息表情 | 不是旋转站姿；实际靠卧关系待整册校样 |
| back | 原地背转，隐藏五官与腹纹 | 带结／领巾结使用背面锚点，不留正脸 |
| side | 身体收窄、单眼侧脸 | 与背转区分；具体朝哪侧服从对象位置 |
| curled | 身体低圆、脚收拢、休息表情 | 不代表本页已经睡着，进入时点服从冻结文字 |
| inflated | 身体放大鼓圆、小脚抬离原接地处 | 不能与揉后脚尖落地或嗝后缩回混用；对应关系待后续映射 |

13种组合共用身体、脚、脸及穿戴区；未把每页做成一个专属pose。旧25种pose的名称、调用和局部位置保留，旧四个隐藏／陪伴／转脸姿态也继续工作。

## 穿戴锚点与兼容接口

仍使用char.pose、at、scale、state、spiral，不改变loadBooks/loadSpecs、data-object身份、data-base-transform或四入口。可选字段char.wear只用于新增组合；省略时不穿新配件，现有书稿无需填写。能力表在tools/character-rig.mjs，未知穿戴或在不支持锚点的旧姿态上请求穿戴会明确报错，避免静默漏画。

| char.wear | 身体内的附着区 | 约束 |
|---|---|---|
| paper | 头部前侧 | 同一片额贴；背转不展示正面额贴，直接拒绝该组合 |
| headband／headband-tilted | 头部／背面带结 | 发带随身体变形，歪角是穿戴状态，不是分享奖励 |
| scarf／scarf-creased | 颈部／背面短结 | 短尾避开腹纹；皱褶不触发情绪状态 |
| vest／vest-creased | 躯干两侧，背面用背片 | 开襟保留腹纹，无口袋、无三物图案，不成收纳对象；皱褶细线主要用于正面读态 |
| blanket-shoulders | 同毯披肩区 | 仅提供披背附着；盖身、毯角、落地与收起继续使用同毯对象，不新增独立帽子或第二条毯子 |

三个区的图形外观均在SVG内部写内联样式，通过固定CSS变量控制显隐，适用于use影子树；不依赖文档选择器穿透。配件和身体共享局部坐标，趴、侧、鼓球时不会独自留在原处。具体脱下的发带／领巾在地面的对象和位置属于后续整册制作，本轮没有做新增热区。

腹纹单独保留为真实DOM中的.spiral。组合姿态用一层与data-rig-body相同的data-spiral-frame变换包住它，腹纹自身只承担旋转；仍可由现有查询、复位及揉圈中心测量找到。背面不显示腹纹。能力表的变换与SVG逐项核对，防止两份坐标漂移；页面.char的原始定位和动画反馈不被改写。

## 回归与实际表现复核

新增tools/verify-character.mjs并接入verify:teeth。专项先在旧库复现手臂问题；修复后检查旧ID、全部引用存在、无symbol裁切视口、背面无五官腹纹、纸屏渲染、腹纹坐标与0／90／360度独立反馈、形变尺度、墨迹边缘余量及穿戴实际像素差。组件校样由真实Chromium渲染，不以零件数量替代看图。

对照现有prop-blanket又发现新披毯曾默认蓝色，而原毯为粉色；先补实际计算填色与原毯一致的回归，确认报“同毯披背与原毯颜色不一致”，再将正／背两种披毯统一为原粉色。未新增另一条毯子或修改现有毯子数据。

生成校样在dist/character-proof/poses.png、wear.png和geometry.json，仅为本地组件检查产物，不成为第五个阅读入口或发布文件。已查看组件姿态、配件与品牌预览；趴伏、侧脸、背转、鼓球、悬脚及穿戴位置可辨，所查组件框内无左右裁切。已更新README截图并复核现有拒水页，以检查共享改动未破坏闭嘴转脸和同杯退开。该检查是本次代理看图，不是作者造型批准或儿童试读。

最终使用Node24执行，涉及Python的验收使用既有Python3.12环境。完整破坏回归只在其临时副本运行，不手动破坏作者工作区。字体字符没有变化，新鲜度及覆盖检查通过，不为SVG组件变动重切子集。
